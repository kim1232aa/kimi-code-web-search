# Kimi Web Tools (Plugin Instructions)

Use the available web tools for search and extraction. The bundled `kimi-code-web-search` tools can target a local or remote gateway; do not assume a gateway address.

## Core Tools

- `web_search`: Execute web or social platform searches across the configured provider pool (Exa, Tavily, Brave, You.com, Firecrawl, Parallel, Jina, Keenable, SearXNG, and custom sources) with automatic health-aware key rotation and fallback.
  - An optional `provider` parameter names a configured provider to try first, for example `web_search({ query: "example project release notes", provider: "brave" })`. An unknown or disabled provider fails explicitly instead of being skipped; on a transient failure the search falls back through the remaining enabled chain.
  - **Budget & retry discipline**: If a provider errors or hits quota limits, do **not** retry it — switch immediately via `provider` to another ready source. Use 1–2 other configured providers for cross-verification only when initial results miss key facts or conflict; stop once key claims are verified.
  - To target **Xiaohongshu (小红书)** or **Twitter/X** directly when platform sources are enabled, prefix the query with `小红书:` or `X:` (for example, `小红书: 机械键盘测评` or `X: OpenAI release`). Do not repeat the platform name in the topic keywords.
- `web_fetch`: Fetch and extract clean readable Markdown/text from any public URL, or extract full post body and top comments from Xiaohongshu and X URLs.
  - Use `web_fetch` when you already have a specific URL; use `web_search` for discovery. Fetch official documentation, source files, release notes, or other primary sources and cite key links before asserting detailed external facts.
  - Treat `web_search` snippets as discovery leads, not full page details or verified comments. Describe comments/replies as verified only when `web_fetch` returns their contents.
- `web_mode`: View or change the active Search Mode (`auto`, `smart`, `required`, `off`). `/web:mode smart` (UI label `Jev 判定`) also accepts `jev`, `自适应`, and `智能判定`. A mid-turn switch takes effect from the next user turn — the current turn's Stop decision is frozen at turn start — while `off` immediately blocks this plugin's web tools.
- `web_status`: Inspect a running gateway without starting it. Use the returned `Dashboard & Gateway URL`, not its bind address.

## Search Mode Policy

- **`auto` (智能联网)**: Call `web_search` or `web_fetch` when the user's question requires current, external, or verifiable facts; otherwise answer from context. Search before answering when the request names a version, API, command flag, error, URL, or entity you cannot confirm from local files, and phrase each query around that claim rather than around the fact that a search is due.
- **`smart` (`Jev 判定`)**: The Jev Smart Classifier decides whether this turn needs web research, using TypeSafe System One, OpenRouter, or an OpenAI-compatible endpoint. An escalated turn follows the same research requirement as `required`; a non-escalated turn can finish without research. Classifier errors, timeouts, or missing credentials fail open by default rather than blocking the answer; configuring `failOpen: false` instead escalates the turn to `required` (fail-closed). Neither outcome is evidence that external claims are true.
  - Kimi prompt input can be text or `ContentPart[]` (including images). When transcript context is enabled, the hook reads the tail of `$KIMI_CODE_HOME/sessions/<wd>/<session_id>/agents/main/wire.jsonl` and sends the classifier `last_assistant_reply` and `recent_tools` on **every** classified turn. `recent_user_context` (the previous user turn) is additionally sent only for short follow-ups of at most 24 characters. Injected `<system-reminder>`, hook, and `system_trigger` messages are ignored. Because this transcript context leaves the machine, select an endpoint appropriate for the conversation's privacy needs, or disable transcript context in the Smart/Jev panel.
- **`required` (始终联网)**: Search **before** drafting your final reply, for what the user's request actually depends on — not an arbitrary query to pass the check. With the default `requiredEvidence: "search"` only a search settles the turn (`web_search` or a recognized external search tool); reading a URL alone does not. With `requiredEvidence: "search-or-fetch"` a URL read also counts. `web_mode` / `web_status` never count. When results miss the point or conflict, rewrite the query and switch providers (never retry a failing one); when unsure of a URL, tool parameter, or command flag, search for it instead of guessing; never fill gaps from memory (`未搜到不等于不存在`). Pass the `session_id` and `turn_id` supplied by the turn's UserPromptSubmit hook; never borrow a different session's identifiers. Smart-escalated turns use the same binding. Kimi Code grants the Stop hook one continuation per turn: it steers a turn that has not searched yet, or whose every lookup failed, to search (again) with another source before the turn ends; the second Stop always lets the turn end, with failures reported as **未验证**.
  - **Kimi subagents**: A subagent has an isolated context and does not inherit the parent turn's binding. Its own unbound web calls do not satisfy or alter the parent turn, and an unbound gateway call is rejected in required mode rather than assigned to another session. Pass the identifiers explicitly only when the subagent is intentionally continuing that same parent turn — a subagent call carrying the current session's binding counts toward that same turn, like any other bound call. Do not assume a subagent type's tool list is fixed; use only tools actually exposed to it, and mark unchecked external facts as **未验证**.
  - **Subagent turn-ends**: The engine fires the Stop hook for every agent scope with the same session_id and no agent identity in the payload, so a subagent's turn-end cannot be distinguished from the main agent's. While any subagent is active (between `SubagentStart` and `SubagentStop`), the Stop gate stays silent and consumes no correction budget; enforcement happens on the main agent's turn boundary. A failed or cancelled subagent never fires `SubagentStop`, so the activity counter is reset when a new user turn begins.
  - **System-trigger turns**: Turns started without a user prompt (background task notifications, goal continuations) are marked through the `TurnStarted` event (`origin_kind=system_trigger`) and skip exactly one Stop evaluation, so the previous user turn's research requirement is never injected into them. A new user prompt clears any stale marker.
  - **Session cleanup**: `SessionEnd` deletes a closed session's ephemeral turn state, and `newTurn` prunes non-override entries older than 30 days (crashed sessions that never ended cleanly). Explicit per-session mode overrides are never removed.
- **`off` (关闭联网)**: Do not call this plugin's `web_search` or `web_fetch`. This setting does not control tools from other plugins or the host.
- **Anti-hallucination**: Absence of search hits does not prove non-existence (`未搜到不等于不存在`). Never invent citations, tool outcomes, or unverified details from memory; report gaps, conflicts, or unverified external claims honestly as **未验证**.
- **Exemptions**: An existing configuration with `enabled: false` always exempts research enforcement. With `exemptWhenNoProvider` enabled (**enabled by default**), an existing configuration with no usable `kimi-code-web-search` search route (no provider key in local credentials or `WEB_TOOLS_<PROVIDER>` environment variables, and no authenticated platform session) exempts mandatory enforcement too and emits a no-route notice. Either case does not make an answer verified: report external facts you could not check as **未验证**.
- **External receipts**: `recognizeExternalWebTools` is **enabled by default**. Recognized external web calls are classified as a search (for example `web_search_exa`, `tavily_search`, `brave_web_search`, `firecrawl_search`, `perplexity_ask`) or a page read (`FetchURL`, `web_fetch_exa`, `tavily_extract`, `firecrawl_scrape`, any call with a `url`/`urls` argument). A search satisfies a required turn; a page read does so only under `requiredEvidence: "search-or-fetch"`. A call reported as an error (Kimi `PostToolUseFailure`, an `isError` result, or text output whose every section is an `Error…` message) counts as attempted but failed; when every lookup failed, the Stop gate steers once to switch sources, then reports **未验证**. Discovery, status, and asynchronous job-start tools do not count. Both `PostToolUse` and `PostToolUseFailure` are observation-only in Kimi Code, so recording is best-effort.
- **Fetch chain (`fetchOrder`)**: An explicit `fetchOrder` is followed exactly, including its position for built-in `http` and without adding providers that were omitted. An empty order preserves the legacy search chain and adds `builtin-http` as its final fallback.
- The mode requires this plugin's lifecycle hooks to be loaded. After installing or updating the plugin, reload the plugin/session before relying on the policy. Hooks fail open on execution errors; the gateway separately rejects this plugin's requests while its mode is off. Never describe failed research, classifier fail-open, or a no-route exemption as verification.

## Dashboard Controls

The Web UI's `SearchModeButton` offers `auto` / `smart` (`Jev 判定`) / `required` / `off` with Global/Session scope. The Smart/Jev classifier panel configures the classifier backend, model, endpoint, credentials, timeout, no-route exemption, external web tool receipt option, and the "Require a search (URL reads do not count)" switch (`requiredEvidence`), and provides a classifier test action. Keep credentials in local configuration only; never place private keys, endpoints, or transcript data in public examples.
